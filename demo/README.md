## 复现与付费界限

先运行离线检查，准备Java17+、Maven及缓存的示例依赖，再按脚本创建尚不存在的外部规范工作根。`prepare.py`在验收约定前增加中文业务错误描述，模板标记`repair-lab-demo-1`，与#15正式矩阵独立。不要手工复制检查点或经验冒充同项目来源。

含人工改动的任务可能不能直接提炼：来源版本链必须能证明是Agent修复。此时明确重置原缺陷，在保留人工注释的稳定现场启动新的来源任务；不要把人的修改归因给Agent。重置只改回源码中的唯一比较符，开始新任务前说明操作；不更改测试/pom。录制中的候选原文和确认信息可供审阅，但新现场仍需自己完成来源核验与人工保存。

源任务验证后，在终端执行`--extract-experience <来源任务ID>`，审阅适用条件与限制后才输入`save <来源任务ID>`。之后在同根受控重置原缺陷，启动新任务并检查实际选中的经验ID；无命中就展示限制，不强迫模型首次修错。每次真实模型运行都消耗额度；脚本不是自动授权新的付费调用，不自动追加重试。
